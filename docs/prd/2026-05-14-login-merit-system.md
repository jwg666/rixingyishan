## 第一部分：登录体系

### 1. 登录策略：延迟登录

- **核心原则**：离线可用，需要云同步时才要求登录
- 未登录状态下可完整使用：创建记录、浏览日历、查看详情、管理设置
- 登录是增值能力，提供云同步、跨端访问、功德排行等功能

### 2. 登录触发时机（智能引导）

三种触发场景：

| 场景 | 触发方式 | 说明 |
|------|---------|------|
| 主动登录 | 设置页"登录"入口 | 用户自行点击 |
| 同步触发 | 需要云同步时自动弹出 | 如手动触发同步、切换设备后 |
| 智能引导 | 首次创建记录后轻提示 | 创建记录后底部弹出"登录可云端保存，不怕丢失"，可关闭，仅提示一次 |

- 智能引导弹窗不阻断操作，用户可关闭继续使用
- 同一设备只提示一次，不重复骚扰

### 3. 登录方式

#### 3.1 手机号验证码登录（全端通用）

- **短信服务商**：阿里云短信（与 OSS 同生态，账号统一管理）
- **验证码策略**：
  - 6 位纯数字
  - 有效期 5 分钟
  - 频控：同手机号 60 秒内最多 1 次
  - 频控：同手机号每日最多 5 次
  - 频控：同 IP 每日最多 10 次
  - 错误码可区分：验证码错误 / 已过期 / 发送超限

#### 3.2 微信一键登录（小程序端优先）

- 小程序端优先展示微信登录入口
- 流程：
  1. 用户点击"微信一键登录"按钮
  2. 调用 `wx.login()` 获取 code
  3. 后端用 code 换取 openid + session_key
  4. 弹出微信"获取手机号"授权按钮
  5. 用户授权后，后端通过微信接口解密获取手机号
  6. 手机号作为账号唯一标识，自动注册或关联已有账号
  7. 签发 access + refresh token

- **微信登录 + 手机号绑定**：手机号是账号唯一标识，微信只是快捷入口
- 同一手机号在小程序微信登录和 App 手机号登录后，是同一个账号

#### 4.2 App / H5 端布局
- 无微信一键登录按钮，仅手机号+验证码
- 其余布局同小程序端

#### 4.3 输入校验
- 手机号：11位数字，1开头，实时校验格式
- 验证码：6位纯数字
- 协议未勾选时，点击登录弹出提示引导勾选

#### 4.4 错误态
| 场景 | 展示方式 |
|------|---------|
| 验证码错误 | 输入框下方红字"验证码错误，请重新输入" |
| 验证码过期 | 红字"验证码已过期，请重新获取" |
| 发送频控超限 | 获取验证码按钮置灰，显示"今日发送次数已达上限" |
| 网络异常 | Toast 提示"网络异常，请稍后重试" |

#### 4.5 倒计时
- 获取验证码后按钮变为 "59s" 递减，到 0 恢复"重新获取"

### 5. Token 机制

#### 5.1 双 Token 方案
| Token | 有效期 | 用途 |
|-------|--------|------|
| Access Token | 2 小时 | 接口鉴权，`Authorization: Bearer ***` |
| Refresh Token | 30 天 | 静默刷新 Access Token |

#### 5.2 刷新流程
1. Access Token 过期 → 前端自动用 Refresh Token 调用 `POST /auth/refresh`
2. 成功 → 拿到新的 Access Token，原请求自动重试
3. Refresh Token 也过期 → 跳转登录页，用户重新登录

#### 5.3 退出登录时 Token 处理
- 调用后端 `POST /auth/logout` 吊销 Refresh Token
- Access Token 自然过期（2小时），不强制全局失效

### 6. 多端登录策略

- **允许共存**：同一手机号可同时在多个设备登录
- 数据各自同步，冲突用 LWW 解决
- 不做互踢，后续可扩展

### 7. 退出登录流程

#### 7.1 操作步骤
1. 设置页点击"退出登录"
2. 弹窗确认："退出后本地记录仍保留，再次登录可合并上传到云端。确定退出？"
3. 确认后：
   - 调用后端接口吊销 Refresh Token
   - 清除本地 Token、userId
   - 暂停上传队列
   - 本地所有记录标记 `needsAccountBind = true`
   - 首页状态栏从"已登录"切换为"未登录"引导

#### 7.2 退出后状态
- 本地记录完全可读可写可新建
- 所有记录的同步状态冻结（不上传不同步）
- 设置页显示"登录"入口

### 8. 合并上传（重新登录时）

#### 8.1 自动同步
1. 登录成功 → 自动将所有 `needsAccountBind = true` 的记录绑定当前 userId
2. 元数据立即通过 `POST /records` 同步到云端
3. 有媒体的记录自动进入上传队列
4. 整个过程后台静默进行，首页状态栏显示同步进度

#### 8.2 冲突处理
- 同步时服务端发现冲突（同 clientRecordId 已存在不同内容的记录）→ 返回冲突标记
- 前端收到冲突后弹窗，显示本地版本和云端版本的摘要对比
- 用户选择："保留本地" / "保留云端" / "两个都保留"
- **无冲突则全程无弹窗，静默完成**

## 第二部分：功德系统

### 1. 核心概念

- 用户每次记录善行获得功德值，功德值由善行标签决定
- 功德值由运营平台配置，用户端不可自定义
- 首页醒目展示用户当前总功德

### 2. 功德获取流程

```
用户填写内容 → 平台智能匹配标签+功德值 → 默认选中一项 → 用户可手动调整标签 → 确认保存 → 功德即时累加
```

### 3. 智能匹配逻辑

- 运营平台为每个标签配置"匹配关键词"（如"关爱动物"标签关联：猫、狗、喂、流浪、救助...）
- 用户输入内容后，前端提取关键词匹配最相关的标签，默认选中
- 匹配不到则默认"其他善行"
- 用户可手动切换标签，切换后功德值跟随变化
- **已保存的历史记录不可修改标签，功德值不可变更**

### 4. 首页功德展示

- 顶部醒目区域显示当前总功德（大数字 + 功德图标 ✨）
- 今日新增功德提示，如"今日功德 +10"
- 点击功德区域可进入排行榜页面

### 5. 排行榜

#### 5.1 榜单维度
| 榜单 | 说明 |
|------|------|
| 总功德榜 | 历史累计功德排行 |
| 日行一善榜 | 今日功德排行，每天重置 |

#### 5.2 展示规则
- 显示 Top 50
- 自己的排名固定在底部展示（即使不在 Top 50 内）
- 每条显示：排名、头像（默认随机色块+首字）、昵称、功德值

#### 5.3 昵称与隐私
- 未设置昵称的用户显示"善心人"+ ID 后 4 位（如"善心人3a7f"）
- 用户可在设置页修改昵称
- **用户可选择不公开、不参与排名**（设置页开关）
- 不参与排名的用户不出现在排行榜中，但自己的功德值正常累加和显示

#### 5.4 更新频率
- 每天更新两次：**中午 12:00** 和 **午夜 00:00**
- 定时任务计算，结果缓存

### 2. 新增 API

#### 登录相关
| 接口 | 方法 | 说明 |
|------|------|------|
| `/auth/sms/send` | POST | 发送验证码 |
| `/auth/sms/verify` | POST | 验证码校验+登录 |
| `/auth/wx-login` | POST | 微信登录（code + 手机号解密） |
| `/auth/refresh` | POST | 刷新 Access Token |
| `/auth/logout` | POST | 退出登录（吊销 Refresh Token） |

#### 功德相关
| 接口 | 方法 | 说明 |
|------|------|------|
| `/merit/tags` | GET | 获取所有启用的善行标签+功德值（前端匹配用） |

| `/merit/my` | GET | 获取我的功德值+今日功德 |
| `/rankings/total` | GET | 总功德榜（从缓存读） |
| `/rankings/daily` | GET | 日行一善榜（从缓存读） |

#### 用户信息
| 接口 | 方法 | 说明 |
|------|------|------|
| `/users/profile` | GET | 获取个人信息（昵称、功德、排名设置） |
